# Snap Bot V2 + Status Bot V2 — V3

مشروع جديد وفق المخطط المعياري الجذري المحصّن الذي قدّمه المالك.

## القرارات المعتمدة

- بيئة التشغيل: **GitHub Actions**، حسب آخر تصحيح من المالك.
- مستودع مشترك، مع تطبيقين مستقلين تشغيليًا ونواة `studio-core` مشتركة.
- لكل بوت Workflows وSecrets وقاعدة بيانات وCache وStorage وسجلات مستقلة.
- Snap: Telegram للتحكم والاستلام، والنشر النهائي على Snapchat يدوي.
- Status: WhatsApp فقط للتحكم والاستلام والنشر اليدوي للحالة أولًا، ثم Outbox معزول وفق بوابات الجاهزية.
- الوكلاء القدامى تُحفظ اختصاصاتهم وأسماؤهم أثناء الترحيل وتُربط عبر Adapters.
- النص الديني يُتحقق منه ضد مرجع مستقل ثم يُقفل، قبل التصميم والرندر والفحص البصري.

## الهيكل

```text
packages/studio-core/   # النواة المشتركة (حزمة studio-core)
apps/snap-bot/          # حزمة snap_bot + اختباراتها
apps/status-bot/        # حزمة status_bot + اختباراتها
config/                 # إعدادات غير سرية وKill switches
docker/Dockerfile       # صورة لكل تطبيق (--build-arg APP=...)
scripts/                # أتمتة البناء والاختبار والنشر والرجوع
.github/workflows/      # CI وCD وRollback وتشغيل كل بوت
docs/
```

## التطوير والتشغيل

```bash
make bootstrap   # uv sync + pre-commit
make lint test   # الفحوص والاختبارات
make images      # صور snap-bot وstatus-bot
make ci          # خط CI كاملًا محليًا
```

## حالة المرحلة 0

اكتُشف المستودعان `Khalidshar/snap-bot` و`Khalidshar/status-bot` من حساب GitHub
المتصل. لم يجرِ جرد كودهما ضمن هذا المستودع بعد. تُقرأ المصادر لإعداد السجل،
وتوثّق أسماء مزودي التصميم من الكود الفعلي قبل ربطهم.

تحتاج المرحلة 0 إلى توثيق استراتيجية حفظ الحالة والملفات بين تشغيلات Actions،
ونمط استقبال الأوامر والجدولة، وحدود الموارد، قبل تنفيذ التشغيل.

لا تُعتبر أي مرحلة مكتملة قبل تحقق معيار خروجها وتوثيق نتيجته.
