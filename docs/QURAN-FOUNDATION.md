# المهمة ٨٨: التلاوة والتفسير للبوتين

## المرجع والنطاق

قُرئ المخطط `ARCHITECTURE_V3_AGREED.md` وملف `DECISIONS.md` قبل البناء.
نص القرآن من ملف مجمع الملك فهد المثبت وحده؛ لا يُجلب نص قرآن بديل من المؤسسة.
المتوفر محليًا هو الجزء المثبت من ملف المجمع، وليس كامل القرآن؛ تُرفض أي آية غير موجودة فيه.
لا تعديل للملف أو الخط أو البصمات أو الحروف أو التشكيل.

المسار الجديد مشترك في النواة، وله مدخل يدوي مستقل في كل تطبيق:
`snap_bot.quran_clip` و`status_bot.quran_clip`. كل مدخل ينتج مقطعًا لآية كاملة ثم
تفسيرها، ولا يملك صلاحية إرسال. تبقى موافقة المالك وبوابات تسليم كل منصة مستقلة.
لا يُستبدل مسار أوامر «آية اليوم» أو أذكار أو الكهف القائم تلقائيًا بهذه الدفعة.
ربط المخرج الجديد بدورة الوكلاء والتسليم القائمة يحتاج اختبار عقد إضافيًا؛ هذه
الدفعة ليست تفعيلًا لهذا الربط ولا ادعاء اكتماله. لم يُنشر شيء على السيرفر.

## البيئة والأسرار

الافتراضي `prelive`. بيئة المؤسسة التجريبية محدودة بالفاتحة والبقرة، وقد لا
تكون كل موارد التفسير أو القراء منشورة فيها. لا نتحول إلى الإنتاج عند نقص مورد.
يحصل التطبيق على الموارد المنشورة فقط، وغياب التفسيرين يمنع المقطع.

يجهّز مسؤول السيرفر ملف `/etc/madar/quran.env` بصلاحية `0600` وملكية `root`،
والدليل بصلاحية تمنع وصول المستخدمين الآخرين. أسماء المتغيرات فقط:

- `QF_CLIENT_ID`
- `QF_CLIENT_SECRET`
- `QF_ENV=prelive`
- `QF_PRODUCTION_APPROVED=no`

لا يُنسخ الملف للمستودع أو المتصفح أو أداة الرندر. لا تستخدم المفاتيح في
وسائط الأوامر أو طلبات المراجعة أو السجلات. لا يُفتح أو يُطبع الملف في التطوير.
وحدها خدمة `studio_core.network.quran` تحمل الملف عبر `EnvironmentFile`.
تجدد رمز الدخول في الذاكرة، وتعيد المصادقة مرة واحدة عند 401؛ لا تحفظ الرمز.
الأخطاء المنشورة رموز ثابتة لا نصوص ردود المؤسسة.

للإنتاج يلزم اعتماد المؤسسة أولًا، ثم تغيير البيئة وإثبات الموافقة في متغير
`QF_PRODUCTION_APPROVED=yes`. هذا حاجز تشغيل محلي وليس طريقة للحصول على اعتمادها.

## القراء المقترحون — غير معتمدين

قائمة حفص المرشحة في `config/quran/reciters.json`:

| القارئ | معرّف المورد المقترح |
|---|---|
| مشاري العفاسي | 7 |
| عبد الرحمن السديس | 3 |
| أبو بكر الشاطري | 4 |
| هاني الرفاعي | 5 |
| محمود خليل الحصري | 6 |
| محمد صديق المنشاوي | 9 |
| سعود الشريم | 10 |
| عبد الباسط عبد الصمد | 2 |

المعرّفات والأسماء مرشحة وتحتاج مطابقة موارد بيئة المؤسسة ومراجعة تسجيلات حفص
قبل اعتماد خالد. `approved_by` فارغ؛ لذلك يرفض المسار العمل افتراضيًا. بعد
مراجعة القائمة واعتمادها يسجل مسؤول المراجعة `approved_by: "خالد"` في تغيير
موثق؛ لا تضع هذا الاعتماد نيابة عن المالك. يطابق الجلب المعرّف مع الاسم العربي
المعاد من المؤسسة؛ اختلافه يؤدي للصمت، ولا يُنسب صوت لقارئ غير متحقق.

لكل بوت قاعدة `audit.sqlite` مستقلة. الحجز تحت قفل SQLite يمنع تتابع قارئ واحد
حتى مع أوامر متزامنة. إعادة نفس المهمة تحتفظ بقارئها ولا تحجز مقطعًا جديدًا.
سجل الحجز لا يُحذف، ولا يعني الحجز أن الفيديو أُرسل. ترتيب التسليم لا يتحكم به
هذا المسار؛ عند ربط التسليم لاحقًا يجب الحفاظ على ترتيب الحجوزات.

## الجلب والتحقق

كل جلب عبر `NetworkClient` ومقبس Unix خاص بكل بوت:
`/run/madar/snap-quran.sock` و`/run/madar/status-quran.sock`.
خدمة الجلب وحدها تفتح اتصال HTTPS: نطاق بيئتها فقط، وCDN التلاوات المحدد في
السياسة، مع فحص DNS والعناوين العامة وتثبيت TLS، بلا إعادة توجيه.
لا تصل ترويسات المصادقة إلى CDN أو إلى بيئة أخرى.

يُستخدم `resources/sync` ثم لقطة المورد المنشور؛ بيانات اللقطة الكاملة في
الذاكرة فقط، ويُحفظ سجل الآية المطلوبة وحده. لا تُبنى قاعدة تفسير من API عادي.
تبدأ كل مهمة جديدة بمزامنة جديدة، ولا توجد قاعدة محتوى دائمة أو مزامنة مجدولة.

التفسير الميسر أولًا، ثم السعدي عند عدم توفر المورد أو سجل الآية. لا تلخيص
ولا إعادة صياغة؛ النص الخام وبصمته محفوظان مؤقتًا. إزالة وسوم التنسيق وفك
كيانات HTML فقط، مع حفظ الفقرات. يُرفض وسم غير مدعوم بدل إسقاط كلامه.
التفسير الذي يغطي مجموعة آيات يُرفض في مسار الآية المفردة لمنع اجتزاء السياق.

الصوت ملف آية مستقل كامل، لا مقطع مقتطع من سورة. يُفحص نوعه وحجمه ومدة صالحة
محدودة، ويُفك ترميزه كاملًا بـFFmpeg لاكتشاف التلف. لا يُستخدم `seek` أو `trim`
أو `shortest` على التلاوة. فشل الجلب أو الفحص ينتج فيديو دون مسار صوتي؛ لا TTS
ولا موسيقى ولا مؤثرات. صوت الاختبارات الاصطناعي اختبار للترميز فقط، وليس عينة تلاوة.

## الإخراج والعمر

الآية أولًا بخط المجمع المثبت، ثم صفحات التفسير بخط النسخ المثبت، داخل نافذة
الإطار الأخضر المعتمد. صفحات النص تحمل مواضعها في الأصل ويُتحقق من عدم نقص أي
حرف. تبقى الآية ظاهرة طوال تلاوتها؛ بعدها التفسير صامتًا بمدة قراءة محسوبة.
إذا تجاوزت الآية الكاملة مع تفسيرها ١٨٠ ثانية يُرفض المقطع بدل القص أو التلخيص؛
هذا المسار لا يقسمه تلقائيًا إلى عدة مقاطع.

النسبة على شاشة الآية: «التلاوة: اسم القارئ — المصدر: مؤسسة القرآن».
وعلى التفسير اسم الكتاب الحقيقي: «التفسير الميسر» أو «تفسير السعدي»، مع المصدر.
في حالة فشل الصوت اسم القارئ هو المحجوز للمحاولة فقط، وتوثق النتيجة `SILENT_AUDIO_FAILED`.

الرندر عملية منفصلة بلا ملف أسرار، مع `PrivateNetwork=yes` و
`RestrictAddressFamilies=AF_UNIX` وحجب `/run/madar` و`/etc/madar`.
يشترط فحص عزل فعلي قبل القراءة، وتقتصر مدخلات فك الصوت على `file,pipe`.
وحدات systemd في الطلب نماذج تثبيت يدوية، بلا `[Install]` أو مؤقتات، ولم تُشغّل.

كل الصوت والتفسير والصور الوسيطة والفيديو الناتج في مجلد `payload/<job>`
داخل جذر خاص بكل بوت. يُحذف المجلد قبل سبعة أيام بدقيقتين؛ عامل عمر الملفات
يمسح كل ٣٠ ثانية ولا يولّد أو يرسل محتوى. لا يعمل بجدولة محتوى أو timer.
يجب تشغيل عامل العمر مع المسار عند نشره؛ النسخة غير المشغلة ليست إثبات حذف حي.
عند توقف السيرفر لا يمكن تنفيذ حذف فيزيائي؛ عند استئنافه يُحذف المنتهي قبل
العمل، ويُرفض استخدام ملف منتهي دائمًا. لا تجديد للعمر عند القراءة أو إعادة المحاولة.

قاعدة التدقيق خارج `payload` ولا تُحذف. تحتوي المعرّفات والأوقات وحالة الحذف
والقارىء فقط، ولا تحمل نص التفسير أو الصوت أو المفاتيح.
لا تنسخ الأصول أو الصور أو الفيديو إلى مكان دائم أو إلى Git أو النسخ الاحتياطية؛
أي نسخة مشتقة تحمل المحتوى تخضع للعمر نفسه، ولا ينفذ هذا المسار نسخًا خارج مجلده.

## المراجعة البشرية والتجربة

بعد اعتماد القراء وتجهيز مفاتيح التجربة وتشغيل عامل العمر والجلب، يستخدم مسؤول
السيرفر مدخل التطبيق يدويًا (`prepare` مع `--root` و`--job` و`--surah 2 --ayah 45`)،
ثم وحدة الرندر الخاصة بالتطبيق ومعرّف المهمة نفسه. معرّف المهمة ٣٢ محرفًا سداسيًا.
الجذور المقترحة `/var/lib/madar/snap/quran` و`/var/lib/madar/status/quran`.
نتيجة الرندر: `render/video.mp4` و`render/ayah.png` و`render/tafsir.png` داخل مجلد المهمة.

المطلوب لشيهانة: صورتا الآية والتفسير، والفيديو لسماع التلاوة، ونتيجة البصمات
والعزل، وموعد انتهاء الصلاحية. الصور وحدها لا تثبت صحة الصوت أو اكتماله.
لم تتوفر مفاتيح المؤسسة أو اعتماد القراء في بيئة البناء؛ لذلك لا عينة حقيقية
من المؤسسة مرفقة، ولا يُستبدل ذلك بتفسير مؤلف أو صوت اصطناعي أو عينة إنتاجية.
لا نسخ للمفاتيح إلى ChatGPT أو GitHub لإكمال هذا الاختبار.
