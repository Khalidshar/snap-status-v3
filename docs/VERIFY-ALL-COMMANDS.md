# التحقق الشامل للبوتين — تشغيل يدوي دون إرسال

تُشغّل شيهانة الأداة **بعد دمج ونشر #91 و#92 و#93**، قبل العمل على لوحة التحكم.
لا تثبّت الأداة خدمات، ولا تبدأ وحدات الإنتاج، ولا تغيّر الجدولة أو مفاتيح التفعيل.

من الإصدار المنشور، بأمر واحد:

```bash
sudo /opt/madar/current/.venv/bin/python /opt/madar/current/scripts/verify_all_commands.py
```

يلزم لينكس وsystemd وحزم الإصدار وأدوات الإخراج المثبتة، ومستخدم الإخراج الموجود
في بيان الإصدار، وبوابتا المصادر والفيديو المعتادتان لكل بوت. لا تقرأ الأداة ملفات
الأسرار ولا تحتاج بيانات حساب تيليجرام أو واتساب. لا تجهّز أو تفعّل خدمات مفقودة؛
تسجّل الفشل. لا تُشغّل تلقائيًا من CI أو cron أو timer.

## النتائج

يطبع الأمر موقع مجلد جديد داخل `/var/lib/madar/verification/`، ثم نتيجة كل أمر.
يأخذ قائمة الأوامر وأرقامها وتسمياتها من `studio_core.commands.COMMANDS` مباشرة،
ويمر عليها كاملة، بالترتيب، لكل من سناب والحالات. لا يحتاج تحديد أسماء يدويًا.

- `report.html`: تقرير عربي باتجاه يمين إلى يسار، يمكن فتحه محليًا دون خادم ويب.
- `report.json`: نتائج كل فحص، وإصدار الكود، وعدد المنجز والمتبقي، وحالة اكتمال التشغيل.
- `frames/`: صورة من كل مقطع أُنتج، حتى عند رفض هويته أو صوته. عند تعذّر المصدر أو
  الإخراج لا تُختلق صورة بديلة؛ يُذكر الفشل. الصور تشخيصية ولا تسمح بإرسال المقاطع.
- مجلد مستقل لكل بوت وأمر: المحتوى، ونتيجة الإخراج، ورد النص إن وجد، والسجلات
  المحلية، و`agents.json` بأدوار الوكلاء الثمانية عشر وحالات التنفيذ الفعلية.

رمز الخروج `0` يعني مرور **كل** الأوامر في البوتين. الرمز `1` يعني وجود فشل، و`2`
خطأ في متطلبات التشغيل أو الوسائط. يتحدث التقرير بعد كل أمر؛ التشغيل المقطوع
يبقى موسومًا بأنه غير مكتمل حتى لو نجحت كل الأوامر التي انتهت قبله.
لا تحذف الأداة تقارير أو سجلات أو أدلة تشغيل سابقة. قد يستغرق التحقق وقتًا طويلًا
لأنه ينتج المقاطع بالتتابع. التشغيل يدوي وتحت إشراف مسؤول السيرفر.

## المسار الحقيقي وحدود التحقق

- المحتوى المحلي في سناب: `snap_bot.server_preview.render_bundle` ثم
  `actions_preview.render_bundle` و`service.execute` والوكلاء والمحرك والفحوص القائمة.
  يستخدم بيان الإصدار ومستخدم الإخراج وعزل systemd الموجودين، دون اعتماد بشري أو إرسال.
- محتوى الحالات والأخبار و«يومك في دقيقة»: `status_bot.content_clips.build` نفسه،
  بقاعدة تحقق جديدة، دون إنشاء مرسل أو استدعاء `send` أو تعديل طابور الإنتاج.
- الأخبار: `collect` عبر Network Core وتهيئة فيديو المصدر والخلفية المعتادة، ثم
  `snap_bot.news_clips.render_event` أو مدخل الحالات نفسه.
- ملخص سناب: `daily_brief.prepare` و`snap_bot.brief.render_event` نفسيهما.
- تُستدعى مداخل الإخراج نفسها داخل وحدات تحقق مؤقتة بجذر أدلة مستقل؛ لا تُستدعى
  وحدات الأوامر التي تجمع الإخراج والإرسال. يُفحص أيضًا وجود قوالب وحدات الإنتاج
  المطلوبة عبر `systemctl show` للقراءة فقط، لكشف مشكلة التثبيت مثل #92.

كل عامل ومُخرج في شبكة خاصة مع `RestrictAddressFamilies=AF_UNIX`. مرحلة المصادر
تستخدم فقط مقبس أخبار التطبيق ومقبس الفيديو المجاني المسموحين، ولا تتصل مباشرة
بالإنترنت. عامل الإخراج يحجب مقابس المصادر أيضًا. تُحجب `/etc/madar`، ولا تُمرر
بيئة الصدفة أو مفاتيحها للوحدات. حاجز إضافي في بايثون يرفض قراءة ملفات البيئة
والاتصالات الشبكية ومداخل نقل تيليجرام وواتساب. أسماء الوحدات المؤقتة فريدة؛
تُوقف وحدات التحقق الخاصة بالتشغيل عند الانقطاع أو الفشل، دون إيقاف وحدات الإنتاج.

`MADAR_QURAN_AUDIO=0` مفروض في تشغيل التحقق فقط: المطلوب في هذه الجولة هو اختبار
`silent_sacred` بعد #93، ولا يغيّر ذلك ملف تفعيل البوتين أو قائمة القراء في #91.

## ما الذي يجعل الأمر فاشلًا؟

- بصمة الملف أو مقاسه أو مدته أو حجمه أو فك ترميزه أو فحص المساحة الآمنة غير صحيح.
- الإطار لا يطابق طبقة الهوية المثبتة بالبصمة. تُركّب الأداة مرجعًا محليًا من الخلفية
  والطبقة الشفافة المثبتة، وتفحص الخلفية والنقش منفصلين خارج نافذة المحتوى في ثلاث لقطات: البداية والوسط والنهاية، مع سماح لضغط الفيديو.
  هذا فحص عينات زمنية، وليس إثباتًا بصريًا لكل إطار أو OCR للنص.
- الديني لا يحمل سياسة `silent_sacred`، أو صوته أعلى من ‎−80 dBFS. يُقاس الملف
  فعليًا، ولا يكفي ادعاء السياسة في JSON. غير الديني يُفحص حسب سياسته؛ الصوت المحيطي
  يعاد قياسه، والخبر الصامت يُقاس صمته، والأصلي يمر بعقد المصدر الأصلي القائم.
- الخبر غير حديث أو مصدره غير معتمد أو نصه أو توقيته تغيّر، أو لم يُثبت وجود المصدر
  والوقت ضمن ملفات النص التي رُسمت فعليًا. الفيديو الأصلي الذي لا يحرق المصدر والوقت
  سيُسجّل فشلًا لهذا البند؛ الأداة لا تضيفهما من عندها.
- الملخص لا يحوي التاريخين والآية والخبر السعودي وخبر التقنية المثبتة، أو يتجاوز
  الدقيقة. يُقاس صمت مقطع الآية الأصلي وفترته داخل الملخص النهائي، مع استبعاد حدّي
  وصل AAC من قياس الفترة؛ يبقى الأصل مفحوصًا كاملًا.
- غياب أي تشغيل ناجح من الوكلاء الثمانية عشر. الجرد الحالي يضع ١٢ دورًا في سلسلة
  المقطع و٦ أدوات محلية مستقلة؛ **وجود ١٨ اسمًا في الجرد لا يكفي للنجاح**. لذلك قد
  تفشل المقاطع في شرط السلسلة مع نجاح الإخراج، ويعرض التقرير ذلك بوضوح. لا تُختلق
  تشغيلات للأدوات، ولا يُعدّل مسار البوت لإخفاء الفجوة.
- رد نصي فارغ أو رد «غير مكتمل» أو تعذّر الأداة أو عدم ثبوت مطابقته لوظيفة الأمر.
  تُستدعى معالجات النص الحالية بحالة محلية جديدة؛ هذا لا يثبت صحة بيانات الإنتاج
  أو نوافذ واتساب الحية. الإيقاف ورفعه والإلغاء تُختبر في حالة تحقق منفصلة فقط.
  أوامر الجدولة غير المكتملة لا تفعّل شيئًا، وتظهر فاشلة. أمر اللوحة يُجرد فقط ولا
  يبدأ بناءها أو تشغيلها. أدوات تحتاج محتوى سابقًا ولا تجده تُسجّل فشلها كما أعادته.

هذه أداة **تكشف** الفشل ولا تصلحه، ولا تعيد إرسالًا، ولا تعتبر غياب الأخبار نجاحًا.
الطلب يضيف السكربت واختباراته وهذه الوثيقة فقط؛ لا يمس ملفات #91 و#92 و#93، ولا
V1 أو V2، ولا يتضمن نشرًا على السيرفر. فحوص GitHub تثبت سلامة الأداة واختباراتها؛
نتائج الأوامر الفعلية لا تُعتمد إلا عند تشغيل شيهانة لها على السيرفر بعد الدمج.
