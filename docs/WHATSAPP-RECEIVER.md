# مستقبِل واتساب v3 المستقل

## لقطة الرجوع قبل التغيير

تمت القراءة من واجهة Meta للتطبيق الموجود يوم الأحد ١ نوفمبر ٢٠٢٦، دون حفظ أو تعديل أي إعداد:

| الإعداد | القيمة غير السرية |
|---|---|
| عنوان الاستقبال الحالي | https://khalid-bot.khalid-sharahili-sa.workers.dev/ |
| الاشتراك المفعّل | messages فقط |
| إصدار الاشتراك | v26.0 |
| العامل القديم | khalid-bot، يبقى دون تعديل أو حذف |
| رمز التحقق وسر التطبيق | لا يُقرأان في الدليل ولا يُكتبان هنا؛ يُدخلان كأسرار فقط |

الرجوع: إعادة العنوان القديم أعلاه في Meta بنفس اشتراك messages وإصداره، مع رمز التحقق القديم عبر الإدخال المخفي لدى خالد. لا تغيير للعامل القديم ولا حذف للأدلة. تُؤجل العودة إذا تعذر التحقق من الرمز؛ لا تخمين أو طباعة له.

## المسار الجديد

Meta → madar-v3-whatsapp (Workers Free) → ربط INBOX لخدمة VPC خاصة محددة → نفق مستقل صادر من السيرفر → جسر 127.0.0.1:8765 → مقبس command-webhook/incoming.sock → WhatsAppOutbox.webhook → command_inbox.

العامل يتحقق من رمز التحقق ومن X-Hub-Signature-256 بواسطة HMAC SHA-256 على البايتات الأصلية. لا يمرر غير الموقّع ولا يقر الطلب حتى يقر المقابس المحلي تثبيت الرسالة. التحقق الثاني من توقيع Meta وهوية المالك وإزالة التكرار يبقى في مسار الواتساب الموجود. لا نسخ JSON أو ترميزه أو تغيير التوقيع في الوسط. الجسر لا يحمل مفاتيح ولا يقبل المضيف أو المسار الخطأ.

لا منفذ وارد في جدار الحماية أو مجموعة AWS. الجسر يستمع على loopback فقط ولا يمكن ضبطه على 0.0.0.0. النفق اتصال صادر؛ الـ VPC Service مقيدة بمنفذ الجسر المحلي فقط، وليست صلاحية للوصول إلى الشبكة كلها. لا Quick Tunnel مؤقت ولا شراء نطاق.

توثيق Cloudflare المستخدم: https://developers.cloudflare.com/workers-vpc/configuration/vpc-services/ وhttps://developers.cloudflare.com/workers-vpc/platform/pricing/ . VPC مجاني خلال beta وفق التوثيق المقروء بهذا التاريخ، والحساب شوهد على خطة Free. لا تقبل ترقية أو إضافة مدفوعة؛ أوقف خطوة النشر إذا لم تعد الميزة مجانية أو تغيرت شروطها.

## إعداد قابل للمراجعة

1. يبقى code العامل في workers/madar-v3-whatsapp/worker.mjs؛ لا يتعامل مع khalid-bot.
2. إنشاء نفق جديد باسم madar-v3-whatsapp، وخدمة VPC من نوع HTTP إلى 127.0.0.1:8765 على هذا النفق فقط. ربطها باسم INBOX بالعامل الجديد. لا نشر عام لخدمة الأصل.
3. سرّا Cloudflare هما VERIFY_TOKEN وAPP_SECRET فقط. القيم لا تدخل wrangler.toml أو git أو الطلب أو السجل. رمز النفق في /etc/madar/whatsapp-v3-tunnel.token بصلاحية 0600 ومالك root، ويُدخل بطريقة مخفية لا تمرره في وسيطات الأوامر.
4. مطابقة INBOX_HOST مع host في إعداد v3 المحلي للمستقبل. لا قراءة لملف الأسرار؛ تُستخدم أسماء المتغيرات فقط. الوحدتان المستقلتان في config/systemd تُراجعان وتثبتان عند النشر؛ لا مؤقتات ولا جدولة.
5. لا تعلن نجاح اختبار التحقق أو تغيير Meta من اختبارات الوحدة. التشغيل الفعلي يحتاج نفقاً سليماً وأسراراً موجودة وخدمة أصل مقيّدة قبل تحويل الرابط.

## بوابات التحويل المطلوبة

- الخطوة ٤: اختبار GET hub.challenge على العامل المنشور يعيد النص نفسه، وPOST بتوقيع غلط يرد 403 دون وصول إلى الأصل. يُبلّغ خالد بالنتيجتين فوراً. اختبارات Node المحلية تغطيهما لكنها ليست إثبات نشر.
- الخطوة ٥: بعد نجاح الاختبارين، تغيير Callback URL في Meta إلى العامل الجديد، مع messages وv26.0 كما في اللقطة، ثم إبلاغ خالد. لا تعديل اشتراكات أخرى.
- الخطوة ٦: يرسل خالد «الحالة» من جواله، ثم يُتحقق من وصول أمر واحد إلى command_inbox في قاعدة v3 دون عرض الرقم أو نصوص أخرى أو مفاتيح. يُبلّغ خالد بالنتيجة. التكرار بنفس message id لا ينشئ أمراً ثانياً.

الحالة عند إعداد هذا الطلب: الكود والاختبارات جاهزان؛ لم يُنشأ النفق أو العامل في الحساب ولم يتغير رابط Meta أو السيرفر. تسجيل الدخول وقراءة الإعدادات فقط. طلب اعتماد خطوة إنشاء الوصول الخاص عند التنفيذ لا يُعد نجاحاً أو تفويضاً لتغيير العامل القديم.
