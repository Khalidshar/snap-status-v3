# الاحتياطي اليدوي على جهاز خالد — WSL

لا يحتاج خدمة مدفوعة، ولا مؤقتات أو جدولة. السكربت لا ينزّل حزمًا ولا ينقل
أسرارًا ولا ينفذ ترقية أو رندر أو إرسال مباشر. يدير وحدات v3 الموجودة فقط.
تشغيل مستمع الأوامر يمكّن تنفيذ أوامر المالك لاحقًا؛ لا تشغّل احتياطيًا حيًا
أثناء بقاء الأساسي حيًا، حتى لو كان الوصول إليه متعذرًا.

## تجهيز مسبق مرة واحدة

- WSL 2 وتوزيعة Linux مجانية مع systemd، ومساحة كافية وFFmpeg والخطوط والأدوات
  المطابقة لبيان الإصدار. تعطيل سكون Windows أثناء التشغيل مسؤولية المالك.
- تثبيت نفس إصدار v3 عبر المثبّت الموثق في `SERVER-RUNTIME.md`؛ التثبيت وحده
  لا يشغّل الخدمات. تثبيت وحدات الأوامر يدويًا بالمسار الموثق لها.
- نقل ملفات الإعدادات السرية خارج Git بقناة آمنة إلى المسارات نفسها، بصلاحيات
  الجذر. لا تطبع محتواها ولا تضفها إلى حزمة أدلة أو وصف طلب.
- بعد إيقاف وحدات الأساسي ومنع تشغيلها مجددًا، نسخ الحالة الكاملة للتطبيق
  من `/var/lib/madar/snap` أو `/var/lib/madar/status`، بما فيها SQLite وWAL
  وملفات النية والإيصالات ومعرّفات التحديثات والطوابير. نسخ SQLite أثناء عمل
  الكاتب غير صالح لهذا الإجراء؛ استخدم إيقافًا متحققًا أو نسخة SQLite متسقة.
- عند وجود نتيجة إرسال مجهولة: سوِّها على الأساسي قبل التحويل. لا تصفر offsets
  ولا قواعد idempotency ولا تشغّل جهازين على نفس الحساب.
- أعد توجيه نفق واتساب إلى WSL باختبار challenge وتوقيع Meta وفق
  `WHATSAPP-RECEIVER.md`. السكربت لا يغيّر Webhook ولا DNS ولا حسابات Cloudflare.
  لا يعلن فحص الخدمات أن مسار واتساب الخارجي جاهز.

## دليل الاستعادة

داخل مجلد التطبيق، يجهّز المشغّل ملف `standby-restore.json` مملوكًا للجذر
بصلاحية `600`: `commit` هو SHA الإصدار المثبت، و`primary_stopped` يساوي true،
و`files` خريطة المسارات النسبية إلى بصماتها SHA-256. يجب أن تشمل قاعدة البيانات
وWAL إن وُجد ودفاتر الإرسال والنية والإيصالات وoffsets؛ لا تضع ملف أسرار فيها.
البصمات تفحص سلامة الملفات المذكورة، ولا تثبت وحدها اكتمال النسخة أو توقف
السيرفر البعيد؛ تأكيد `--primary-fenced` مسؤولية المشغّل بعد تحقق مستقل.
لا يُستعمل هذا الملف لاحقًا كنسخة احتياطية آلية أو دليل جاهزية دائم.

## التشغيل من طرفية WSL

```sh
sudo python3 scripts/wsl_standby.py check --app snap
sudo python3 scripts/wsl_standby.py start --app snap --primary-fenced
sudo python3 scripts/wsl_standby.py status --app snap
sudo python3 scripts/wsl_standby.py stop --app snap
```

استبدل `snap` بـ`status` للتطبيق الآخر؛ لكل تطبيق قفل وسجل وملف حالة مستقل.
`check` هو الافتراضي، ولا يشغّل شيئًا. لا يوجد enable أو restart أو حذف سجلات.
`stop` يوقف فقط الوحدات المسجلة ضمن محاولة هذا السكربت، ويبقي سجل التدقيق.
عند فشل start لا تعاود تلقائيًا: نفّذ stop وافحص الحالة قبل قرار جديد.
للعودة: أوقف الاحتياطي، تحقق أن وحداته خاملة، انقل الحالة الأحدث المتسقة إلى
الأساسي دون استبدال الأدلة التاريخية، وأعد مسار واتساب، ثم شغّل الأساسي وحده.

لم يُنفّذ على جهاز خالد؛ الاختبار محلي ببدائل systemctl. صلاحية WSL الفعلية
وتسوية الإرسال وملاءمة النفق تحتاج اختبار قبول على الجهاز قبل اعتماد الجاهزية.
